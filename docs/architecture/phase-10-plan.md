# Phase 10 계획: Field Case Study

**상태:** GROWING (진행 중)

**시작일:** 2026-08-03

**성격:** 현장 사례 연구 단계 — Phase 9가 네 가치를 공개 기록으로 채웠다면, Phase 10은 그중 M.ERCY를 실제 현장 도구의 근거로 증명한다. 관찰에서 구현, 검증, 공개까지 한 프로젝트의 전 과정을 하나의 사례로 연결한다.

## 목적

현장에서 관찰한 마찰이 어떻게 안전 경계를 지킨 소프트웨어가 되는지 공개 가능한 형태로 보여 준다. 기술 스택이 아니라 **누구의 어떤 부담이 줄었는가**를 증거로 남긴다.

## 대상

내시경 예약·스케줄 관리 도구([endoscopy-scheduler](https://github.com/corcoidum/endoscopy-scheduler)). 소규모 내과의원 내부용 MVP이며 EMR을 대체하지 않는다. FastAPI·Jinja2·HTMX 기반, 예약과 일정 관리에 필요한 최소 정보만 저장한다.

## 경계

- **실제 환자·직원 정보는 공개물에 들어가지 않는다.** 공개 기록·화면·예시는 합성 데이터로만 만든다.
- 위치·기관을 특정할 수 있는 표현은 공개판에서 일반화한다.
- 도구는 진단·치료·검사 필요성을 판단하지 않는다. 의료진이 이미 정한 운영 업무를 정리하고 누락 가능성을 보여 줄 뿐이다.
- 공개 기록은 기존 발행 gate(검토 증적 → 사람 승인 → 배포 → published_at)를 그대로 통과한다.

## 단계

1. **관찰** — 예약 한 건에 딸려 오는 확인들과 그 부담을 비식별 기록으로 남긴다.
2. **경계와 구현** — 데이터 최소화, 감사 로그, 권한 분리 같은 안전 결정을 공개 가능한 근거로 정리한다.
3. **검증** — 합성 데이터 기반 테스트와 운영 전 보안 점검(기본 비밀값 부팅 가드, 세션 쿠키 보호 등) 결과를 기록한다.
4. **연결** — Projects의 사례 연구로 묶어 관찰·시스템·사람의 결과를 한 흐름으로 보여 준다.

## 완료 기준

위 네 단계가 각각 승인·발행된 공개 기록으로 남고, Projects에서 하나의 사례 연구로 연결되면 완료 검증을 논의한다. 그 전까지 로드맵 상태는 GROWING으로 유지한다.
