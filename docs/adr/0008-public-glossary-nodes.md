# ADR-0008: 승인된 공개 용어 node와 본문 용어 표시

**상태:** 승인됨

**날짜:** 2026-07-25

## 맥락

[ADR-0004](0004-public-knowledge-graph-foundation.md)는 첫 구현을 note-to-note only로 제한하면서 `concept`·`principle` 같은 non-note registry를 명시적으로 미뤘고, 조건을 하나 남겼다. "non-note node가 실제 탐색 요구가 되었을 때 별도 ADR로 registry의 권위 원천과 review lifecycle을 결정한다."

그 요구가 생겼다. 공개 기록이 17편이 되면서 `폴백`, `승인 증적`, `결정론적 빌드`, `재식별`, `publish_state` 같은 운영 용어가 여러 글에 반복 등장한다. 지금은 글마다 같은 용어를 문장 안에서 다시 풀어 쓰거나, 풀어 쓰지 않고 독자가 알고 있다고 가정한다. 앞의 방식은 글이 늘어질수록 같은 설명을 반복하고, 뒤의 방식은 독자를 다른 글로 이탈시킨다. 용어 설명은 note-to-note 관계로 표현할 수 없다. 용어는 글이 아니라 글 안의 한 단어이기 때문이다.

동시에 위험이 둘 있다. 첫째, 본문에서 키워드를 문자열로 찾아 자동으로 링크를 다는 것은 이 저장소가 금지한 자동 관계 추론이며, "사람이 frontmatter에 직접 선언한 관계만 edge가 된다"는 공개 계약과 충돌한다. 둘째, 이 기능은 이미 승인·발행된 본문의 표시를 사후에 바꾼다. 어떤 단어가 링크로 바뀌는지가 검토 없이 달라지면 승인 증적의 의미가 약해진다.

규모는 문제가 아니다. 2026-07-25 실측으로 `index.json`은 30KB(gzip 11KB), `graph.json`은 11KB(gzip 1.9KB)다. [ADR-0006](0006-content-scaling-ladder.md) 사다리 1단 트리거(노트 약 50편 또는 gzip 50KB)까지 여유가 있고, 용어 node 15개를 더해도 계단을 앞당기지 않는다.

## 검토한 선택지

1. **별도 glossary registry 파일**(JSON 또는 YAML)에 용어를 선언한다.
2. **용어도 `CORCOIDUM-Public`의 note로 만든다.** `note_kind: glossary`로 구분한다.
3. **각 기록의 frontmatter에 용어 앵커를 직접 선언한다.**

선택지 1은 새 권위 원천을 만든다. 검증기·검토 증적·승인 절차를 우회해 콘텐츠를 넣을 수 있는 뒷문이 생기고, ADR-0006의 "공개 콘텐츠의 권위 원천은 계속 Markdown frontmatter + git"과 차터의 단일 권위 원천 원칙이 함께 깨진다.

선택지 3은 가장 정확하지만 같은 용어를 쓰는 모든 기록에 중복 선언이 쌓인다. 용어 설명이 바뀌면 그 용어를 언급한 모든 노트의 frontmatter를 고쳐야 하고, frontmatter 변경은 검토 증적을 무효화하므로 승인된 기록이 연쇄적으로 `draft`로 되돌아간다.

선택지 2는 용어를 기존 발행 하네스 안에 그대로 넣는다. 용어 node도 민감 패턴 검사, privacy 검토, 사람 승인, 결정론적 빌드를 똑같이 통과하며, 새로운 권위 원천도 새로운 검토 수명주기도 만들지 않는다.

## 결정

- **용어 node는 `CORCOIDUM-Public`의 note다.** frontmatter에 `note_kind: glossary`를 선언하며, `note_kind`가 없으면 기존과 동일한 기록으로 취급한다. 검증·검토·승인·발행 절차는 기존 기록과 완전히 같다.
- **`note_kind`는 닫힌 집합이다.** `classification`·`visibility`·`publish_state`와 같은 방식으로 `schemas/note-frontmatter.schema.json`의 enum과 검증기 상수에 값을 고정하고, 목록에 없는 값은 검증에서 거부한다. 최초 값은 `glossary` 하나다. 자유 문자열로 두면 `note_kind: glosary` 같은 오타가 검증을 통과한 뒤 용어 목록에서만 조용히 빠져 사전 항목이 일반 기록으로 발행되며, 이 실패는 게이트가 전부 통과한 상태로 사람 눈에 띌 때까지 남는다. 종류를 추가할 때 검증기 수정과 커밋이 필요한 것은 비용이 아니라 의도된 검토 지점이다.
- **하이라이트 대상 문자열은 용어 node가 `aliases`로 스스로 선언한다.** 다른 기록은 아무것도 선언하지 않으며, 본문을 수정하지 않는다. 선언의 방향을 용어 쪽으로 모아 승인 증적의 연쇄 무효화를 피한다.
- **매칭은 결정론적 부분 문자열 탐색만 사용한다.** alias가 본문에 부분 문자열로 등장하면 해당 구간을 표시한다. 한 기록에서 같은 용어는 **겹치지 않는 첫 등장** 1회만 표시하고, 용어 node 자신의 본문은 제외한다. 긴 alias를 가진 용어가 먼저 구간을 차지하며, 짧은 용어의 첫 등장이 그 안에 삼켜지면 뒤쪽의 겹치지 않는 등장을 찾는다. 첫 등장이 삼켜졌다는 이유로 용어가 통째로 사라지지 않게 하기 위해서다. 형태소 분석·유사도·embedding·LLM은 쓰지 않는다.
- **부분 문자열 탐색을 택한 이유는 한국어 조사다.** 조사는 낱말 뒤에 붙으므로(`폴백` → `폴백이`·`폴백을`·`폴백으로`) 앞부분만 찾으면 조사 형태를 규칙으로 다루지 않아도 된다. 어절 단위 일치는 조사 형태를 전부 alias로 나열해야 하고 빠뜨린 형태가 조용히 누락되므로 채택하지 않는다. 조사까지 표시 구간에 포함하는 방식은 조사 목록을 관리해야 하는데 `폴백이라는`에서 `폴백이`만 덮이는 등 결과가 오히려 나빠지므로 채택하지 않는다. 표시 구간은 alias까지만이며 뒤따르는 조사는 표시 밖에 남긴다.
- **부분 문자열 탐색의 부작용은 두 가지 규칙으로 막는다.** alias는 세 글자 이상만 허용해 짧은 낱말이 다른 낱말 안에 걸리는 것을 차단하고(`노트` → `노트북`), 띄어쓰기 변형은 추론하지 않고 사람이 `aliases`에 함께 선언한다(`승인 증적`, `승인증적`).
- **매칭 결과는 `content/public/glossary.json`으로 굳히고 `--check` 회귀 검사 대상으로 둔다.** 어떤 단어가 어느 기록에서 표시되는지가 결정론적 산출물로 남아 git diff와 Pull Request에서 검토된다. 기계가 위치를 찾더라도 결과는 사람이 승인한 커밋으로만 배포된다.
- **용어 node는 `graph.json`의 node나 edge가 되지 않는다.** 지식 그래프는 note-to-note only를 유지하며, ADR-0004의 그래프 결정을 대체하지 않는다. 이 ADR은 그래프가 아니라 본문 표시 계층을 다룬다.
- **`index.json`은 `notes`와 `glossary`를 분리한다.** `/garden` 목록, `/graph`, `/lab` 검색은 `notes`만 소비해 용어 항목이 기록 사이에 섞이지 않게 한다.
- **표시는 2단으로 한다.** 1단은 용어 node 첫 문단에서 잘라낸 짧은 설명, 2단은 기존 note modal과 `?note=<id>` deep link를 그대로 재사용한다. 새 상세 화면을 만들지 않는다.
- **접근성 요구를 구현 조건으로 둔다.** 용어는 `<span>`이 아니라 `<button>`으로 렌더하고, hover와 keyboard focus 양쪽에서 열린다. 말풍선은 Esc로 닫히고, 말풍선 위로 포인터를 옮겨도 유지되며, 시간 경과로 저절로 사라지지 않는다(WCAG 2.2 §1.4.13). 포인터가 없는 화면에서는 탭으로 1단을 열고 말풍선 안의 이동 control로 2단에 들어간다.
- **본문 렌더는 텍스트 노드 분할로 구현한다.** `innerHTML`은 쓰지 않는다.
- **최초 도입 범위는 `/garden` 본문으로 한정한다.** `/hope`·`/trust`·`/mercy`·`/love` 가치 공간, `/lab` 검색 결과, `/graph` 상세 panel에는 적용하지 않는다. 한 화면에서 읽기 방해·접근성·모바일 동선을 먼저 확인한 뒤 넓힌다.

## 경계

- LLM, embedding, 유사도 계산, 형태소 분석, 외부 API, database를 사용하지 않는다.
- 용어 node는 지식 그래프의 edge를 만들지 않는다.
- `draft`·`review`·`archived` 용어 node는 공개 빌드에서 제외한다. 승인되지 않은 용어는 본문에 표시되지 않는다.
- 하이라이트는 승인된 본문의 **표시**만 바꾸며 노트 파일을 수정하지 않는다. 따라서 기존 기록의 검토 증적을 무효화하지 않는다. 대신 표시 변경분은 `glossary.json` diff로 검토한다.
- `ClinicOps-Local`, `CORCOIDUM-Core` 콘텐츠는 소비하지 않는다.
- 한 문단이 형광펜으로 덮이지 않도록 첫 등장 1회 규칙은 표시 옵션이 아니라 빌드 규칙으로 강제한다.

## 결과

독자는 글을 떠나지 않고 용어의 짧은 뜻을 확인하고, 필요할 때만 상세로 들어간다. 작성자는 같은 설명을 글마다 반복하지 않아도 되고, 용어 정의를 한 곳에서 고치면 모든 기록에 반영된다. 용어가 기존 발행 하네스 안의 note이므로 새로운 검토 절차나 권위 원천이 늘지 않고, 표시 대상은 결정론적 산출물로 감사할 수 있다.

상세 modal·`?note=<id>` deep link·focus 복귀는 이미 구현되어 [ADR-0007](0007-read-only-knowledge-map.md)이 Knowledge Map에서 재사용하고 있으므로, 새로 만드는 것은 본문 tokenize 렌더러와 말풍선 두 가지다. 이 저장소에는 tooltip·popover 패턴이 아직 없으므로 말풍선이 이 변경의 실질적 난이도이며, 키보드·터치·Esc 동작을 Playwright 회귀에 먼저 추가한 뒤 구현한다.
