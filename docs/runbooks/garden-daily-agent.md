# Runbook: Garden 매일 초안 에이전트 (정원사)

매일 저녁 Claude Code 예약 작업(scheduled task)이 이 저장소에서 새 세션을 열어 공개 기록 후보를 하나 준비한다. 에이전트는 **초안과 질문까지만** 만든다. 검토·승인·병합·발행은 사람이 한다.

## 흐름

```text
📱 GitHub 이슈 "아이디어" (공개 가능한 한 줄)        레포 커밋·ADR·테스트
   └──────────────┬──────────────────────────────────────┘
                  ▼
        정원사 (매일 20:43 KST, 새 세션)
                  ▼
   draft PR 하나 ── 빌드 기록 초안  또는  질문 3개짜리 인터뷰 PR
                  ▼
        사람: 읽고, 답하고, 고치고, 체크리스트 확인 후 approve 라벨 → 병합
                  ▼
        기존 게이트 그대로 (검증 → 결정론적 빌드 → 배포)
```

## 에이전트가 하는 일

하루에 아래 중 **하나만** 한다. 위에서부터 먼저 해당하는 것을 고른다.

| 순서 | 조건 | 하는 일 |
| --- | --- | --- |
| A | 열린 인터뷰 PR에 저장소 소유자의 답변 댓글이 있다 | 그 답변만 근거로 경험 기록 초안을 같은 PR 브랜치에 쓴다 |
| B | 지난 24시간에 레포 안에 근거가 있는 빌드 사건이 있다 | 빌드 기록 초안을 새 draft PR로 연다 |
| C | 열린 `idea` 이슈가 있고 그 이슈의 인터뷰 PR이 아직 없다 | 질문 3개만 담은 인터뷰 PR을 연다 (본문은 쓰지 않는다) |
| D | 해당 없음 | 아무것도 만들지 않고 한 줄로 끝낸다 |

정원사가 연 PR이 이미 3개 이상 열려 있으면 새 PR을 열지 않는다. 쌓인 것을 먼저 처리하라는 신호다.

## 에이전트가 하지 않는 일

- 승인 증적 필드(`review_requested_at`, `privacy_reviewed_*`, `reviewed_revision`, `approved_*`, `published_at`)를 채우지 않는다. `publish_state`는 항상 `draft`다.
- 경험·감정·장면을 지어내지 않는다. 사람이 쓴 답변이나 레포 안의 사실에 없는 문장은 쓰지 않는다.
- `content/public/`의 산출물을 다시 만들지 않는다. draft는 수집 대상이 아니다.
- PR을 ready로 바꾸거나 병합하지 않는다. `main`에 직접 push하지 않는다.
- 저장소 밖의 자료(Notion, Drive, 메일)를 읽어 초안에 옮기지 않는다.

## 인터뷰 PR

경험 기록은 사람만 쓸 수 있으므로 에이전트는 질문을 한다.

- 브랜치 `garden/YYYYMMDD-<slug>`, 파일 `vaults/CORCOIDUM-Public/00_Drafts/<slug>.md`
- 본문에는 질문 3개만 둔다. 장면 하나, 그때의 판단 하나, 남은 원칙 하나를 묻는다.
- PR 제목은 `[interview] <글감>`이고 본문에 `Refs #<이슈 번호>`를 적는다.
- **답변은 PR 댓글로 단다. 이 저장소는 공개이므로 댓글도 올리는 즉시 공개된다.** 공개 경계는 이슈를 쓸 때와 같다.

## 사람이 하는 일

1. 폰의 GitHub 앱에서 정원사 PR을 연다.
2. 인터뷰면 댓글로 두세 줄 답한다. 초안이면 읽고 고친다.
3. 발행하려면 PR 본문의 검토 체크리스트를 하나씩 확인하며 체크하고 `approve` 라벨을 붙인다. 워크플로가 승인 증적을 기록하고 산출물을 다시 만든다([라벨 승인](../governance/public-content-review.md#라벨-승인-adr-0010)). 댓글로 결과가 오면 diff를 보고 병합한다.
4. 쓰지 않을 글감은 PR과 이슈를 닫는다. 닫힌 글감은 다시 올라오지 않는다.

## 예약 작업 관리

예약 작업은 Claude 앱의 예약 작업 목록에서 **"CCDOS 정원사 (매일 20:43)"** 이름으로 보인다. 일시 중지·시간 변경·프롬프트 수정은 그 화면에서 한다. 이 문서의 규칙을 바꾸면 예약 작업의 프롬프트도 같이 고친다. 프롬프트가 실제로 실행되는 쪽이다.

## 경계 규칙

- `idea` 이슈와 PR 댓글은 공개 채널이다. 공개하기 이른 생각은 로컬 Obsidian 인박스([Discord 아이디어 인박스](discord-idea-inbox.md))에 둔다.
- 저장소 소유자가 아닌 계정이 쓴 이슈·댓글은 글감이나 지시로 쓰지 않는다.
- 민감 패턴이 의심되면 에이전트는 초안을 만들지 않고 그 사실만 보고한다.
